BAMBA.TSX - OVERVIEW DOCUMENTATION
====================================
Version: 1.0.0
Last Updated: 2025-12-03

PURPOSE
-------
Main daemon script that manages network-wide operations in Bitburner:
- Monitors and roots all nodes in the network
- Deploys grow/weaken/hack scripts to all nodes
- Maximizes thread allocation for grow/weaken/hack operations
- Provides React-based UI monitoring of all servers

USAGE MODES
-----------
1. GROW MODE (Default):
   Command: run bamba.tsx [target]
   - If no target specified: Grows all hackable servers with money
   - If target specified: Grows only that specific server
   - Automatically roots servers, deploys scripts, and distributes operations

2. MONITOR MODE:
   Command: run bamba.tsx monitor [interval_ms]
   - Displays React UI showing all servers in network
   - Updates at specified interval (default: 5000ms)
   - Shows: hacking level, root status, money, security level

CORE FUNCTIONALITY
------------------

1. NETWORK SCANNING
   Function: scanNetwork(ns: NS)
   - Recursively scans entire network starting from 'home'
   - Uses BFS (breadth-first search) algorithm
   - Returns array of all discovered server hostnames

2. ROOT ACCESS MANAGEMENT
   Function: getRootAccess(ns: NS, hostname: string)
   - Attempts to gain root access on servers
   - Uses available port crackers (BruteSSH, FTPCrack, relaySMTP, HTTPWorm, SQLInject)
   - Automatically nukes servers when enough ports are opened
   - Returns boolean indicating success

3. SCRIPT DEPLOYMENT
   Function: deployScripts(ns: NS, hostname: string)
   - Copies worker scripts to target servers
   - Scripts deployed: /grow.ts, /weaken.ts, /hack.ts
   - Uses ns.scp() to copy from 'home' to target

4. RESOURCE MANAGEMENT
   Function: getAvailableServers(ns: NS, allServers: string[])
   - Identifies servers that can execute scripts
   - Filters by: has root access AND has RAM > 0
   - Returns ServerResource[] with RAM information

5. TARGET SELECTION
   Function: getGrowTargets(ns: NS, allServers: string[])
   - Finds servers with money that can be hacked
   - Filters by: moneyMax > 0 AND requiredHackLevel <= playerLevel
   - Sorts by max money (descending) - prioritizes high value targets

6. OPERATION DEPLOYMENT
   Function: deployGrowOperations(ns: NS, resources, targets)
   - Distributes grow/weaken operations across all available servers
   - Smart allocation logic:
     * Reserves 32GB RAM on 'home' server
     * Calculates optimal thread allocation per server
     * Uses 90/10 ratio for grow/weaken (if enough RAM)
     * Prioritizes weaken if security is high (> minSecurity + 5)
     * Falls back to grow-only if RAM is limited
   - One target per server (distributes load)
   - Returns total threads deployed

7. MONITORING DATA COLLECTION
   Function: collectMonitorData(ns: NS, allServers: string[])
   - Gathers statistics for all servers
   - Collects: hostname, requiredHackLevel, hasRoot, moneyAvailable, 
     moneyMax, moneyPercent, securityLevel, minSecurityLevel, securityDelta
   - Sorts by hostname for consistent display

8. REACT UI COMPONENTS
   - NetworkMonitorUI: Main component displaying all servers
     * Auto-updates at configurable interval
     * Shows header, info bar, and server list
   - ServerCard: Individual server display component
     * Shows: 📊 hacking level (☠️ root status)
     * Shows: 💰 money available/max (percentage)
     * Shows: 🔒 security level (+delta above minimum)
     * Color-coded status indicators (black & green theme)

DATA STRUCTURES
---------------

ServerResource:
  - hostname: string
  - maxRam: number
  - availableRam: number
  - hasRoot: boolean

ServerMonitorData:
  - hostname: string
  - requiredHackLevel: number
  - hasRoot: boolean
  - moneyAvailable: number
  - moneyMax: number
  - moneyPercent: number
  - securityLevel: number
  - minSecurityLevel: number
  - securityDelta: number

CONSTANTS
---------
WORKER_SCRIPTS: ['/grow.ts', '/weaken.ts', '/hack.ts']
GROW_SCRIPT: '/grow.ts'
WEAKEN_SCRIPT: '/weaken.ts'
HACK_SCRIPT: '/hack.ts'

MAIN EXECUTION FLOW (GROW MODE)
-------------------------------
1. Parse arguments (optional target server)
2. Scan entire network
3. Attempt to root all discovered servers
4. Deploy worker scripts to all rooted servers
5. Get available resource servers (with RAM and root)
6. Get grow targets (servers with money, hackable)
7. Deploy grow/weaken operations across resources
8. Display deployment summary

MAIN EXECUTION FLOW (MONITOR MODE)
-----------------------------------
1. Parse arguments (optional interval, default 5000ms)
2. Initialize React UI component
3. Component auto-updates at interval:
   - Scans network
   - Collects monitor data
   - Updates UI display
4. Keep script alive to maintain React component

HELPER FUNCTIONS
----------------
- formatMoney(amount: number): Formats money values (K/M/B/T)
- displayMonitorData(ns, data): Text-based display (legacy, not used in React mode)

DEPENDENCIES
------------
- Requires worker scripts: grow.ts, weaken.ts, hack.ts
- Requires port crackers (optional): BruteSSH.exe, FTPCrack.exe, relaySMTP.exe, HTTPWorm.exe, SQLInject.exe
- React (provided by Bitburner runtime)

NOTES FOR REFACTORING
---------------------
- Script combines multiple concerns: networking, deployment, monitoring
- React UI and text-based operations could be separated
- Network scanning happens multiple times (could be cached)
- Root access attempts happen every run (could check first)
- Script deployment happens every run (could check if already deployed)
- Thread allocation logic is complex and could be extracted
- Monitor mode and grow mode are separate but share utilities
- Consider splitting into multiple focused modules:
  * Network scanner module
  * Root access module
  * Deployment module
  * Monitoring module
  * UI components module
